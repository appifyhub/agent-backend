## Why

Partners can generate and edit images in chat, but they cannot yet generate videos or receive them through native Telegram and WhatsApp video delivery. Replicate now exposes a useful set of text-to-video and reference-image-to-video models, so the service needs a provider-backed video generation capability, video-aware accounting, and platform video media support.

## What Changes

- Add one Replicate-only `videos_gen` tool purpose and persisted user tool selection for video generation.
- Add one `generate_video` LLM tool that accepts a prompt plus optional, ordered reference-image attachment IDs and/or external URLs; no references means text-to-video, while references enable image-conditioned generation.
- Add P-Video, Seedance 2.0, Seedance 2.0 Fast, Veo 3.1, Veo 3.1 Fast, and Ray 3.2 to the external tool catalog with normalized duration, aspect-ratio, resolution, capability, and pricing metadata.
- Normalize video duration into optional `short`, `medium`, and `long` tiers, defaulting to `medium` and mapping unsupported tiers to a supported duration instead of rejecting them.
- Normalize video sizes as `1K`, `2K`, and `4K`, mapping them to 720p, 1080p, and 2160p/4K respectively and clamping requests to each model's supported output.
- Resolve omitted aspect ratio from the first reference image when present or `16:9` otherwise, reuse image-style closest-aspect-ratio fallback for explicit values, and map `match_input_image` to each provider's native input-ratio behavior.
- Add a screenwriter prompt-upscaling variant using the existing copywriting tool selection, while disabling provider prompt rewriting where configurable.
- Disable provider safety filtering on every selected model that exposes such an input.
- Add video-per-second costs in credits, where one credit is one US dollar cent, together with output video size and duration usage metadata.
- Launch video generation in bounded background workers, return an immediate generating result to chat, poll Replicate through its SDK with a ten-minute deadline, cancel timed-out predictions, and deliver success or failure asynchronously.
- Add video classification and inbound video mapping for Telegram while retaining and testing the existing WhatsApp inbound video path; MP4 is treated as video, not audio.
- Add cross-platform FFprobe/FFmpeg video inspection, conversion, resizing, bitrate reduction, and size-limit enforcement.
- Add native Telegram and WhatsApp video APIs and smart SDK delivery, including multipart Telegram documents and public-URL WhatsApp documents according to the existing media preference.
- Preserve video-to-video editing as a future possibility but exclude video inputs, video editing, video extension, last-frame inputs, input audio, HDR, EXR, looping, and other advanced controls from this change.
- Require a manual code-review stop after every implementation milestone; work cannot proceed to the next milestone without explicit user approval.

## Capabilities

### New Capabilities

- `video-generation`: Replicate video tool selection, model catalog, normalized inputs, prompt upscaling, pricing and usage accounting, bounded asynchronous execution, and generated-video lifecycle.
- `platform-video-media`: Video classification, inbound Telegram and WhatsApp video ingestion, portable video preparation, native platform video sending, and preference-aware delivery.

### Modified Capabilities

None.

## Impact

- Affected domain and persistence: external tool types and definitions, user tool choices, usage records, database models, repositories, mappers, profile/settings merge behavior, intelligence presets, API contracts, API documentation, and an autogenerated Alembic migration.
- Affected chat orchestration: LLM tool library, prompt library and resolvers, DI factories, background execution, usage tracking, and generated attachment persistence.
- Affected integrations: Replicate prediction creation and polling, Telegram inbound models/API/SDK, WhatsApp inbound models/API/SDK, and the shared platform bot SDK.
- Affected media handling: supported-file classification, attachment resolution for IDs and external URLs, temporary-file streaming, FFprobe inspection, and FFmpeg conversion.
- Affected deployment and CI: continue using the Debian FFmpeg package in the Linux x86 Docker image, document native FFmpeg for macOS ARM development, and make FFmpeg available to GitHub-hosted Ubuntu tests.
- No video provider other than Replicate is introduced.

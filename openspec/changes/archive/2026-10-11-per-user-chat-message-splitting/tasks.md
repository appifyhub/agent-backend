## Execution Rules

Implement bottom-up. Each milestone includes its owning-layer tests and an explicit manual-review stop. Never start the next milestone without the user's approval. Use existing test modules, managed production DI, shared stubs/fakes, and public subject-layer assertions; no new test files are planned.

Keep test changes minimal: review existing cases first and extend them alongside the other settings. Add a new case only for a distinct consumer-visible failure introduced by changed logic and not already covered. Do not add flag-only CRUD/authorization tests, standard boolean validation/coercion tests, or value/platform/role matrices merely because a field was added. General requests to test do not authorize exhaustive coverage.

Initial authorization covers task 1.1 only, followed immediately by focused tests, an offline persistence smoke, the complete offline suite, and repository-wide Ruff/spacing checks. Stop for review after that task. Migration generation remains user-controlled and must not be silently marked complete.

Backend review commands: `pipenv run pytest -v`, `pipenv run ruff check .`, and `pipenv run python tools/check_spacing.py .`. Run the required Ruff/spacing fix commands on changed Python files first. Do not fix unrelated failures.
